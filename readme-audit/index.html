流量来了，
别让首屏漏掉。

README 不能让项目凭空走红。它能做的是：让已经点进来的人迅速看懂、相信，并知道下一步怎么做。

相关性 ≠ 因果

15 个高增长仓库的结构观察只能作为检查线索，不能证明某个元素会带来 Star。

不滚动的一屏，至少回答三件事

项目名 一句话：谁能用它解决什么问题 真实产品截图 / CLI 输出 / 结果样例 一个最短安装或在线体验入口 三条以内的真实差异
01 · VALUE

读者得到什么

“基于 AI 的强大项目”没有对象、用途和差异。先写给谁，再写解决什么。

02 · PROOF

真实结果是什么

可视项目放真实截图；CLI 项目放真实输出。不要用设计稿代替运行证据。

03 · ACTION

下一步是什么

安装、Demo、文档选一个主入口。十几个徽章不能替代开始使用的路径。

04 · DIFFERENCE

为什么选你

写可验证差异：覆盖范围、运行方式、数据来源、边界。少用“最强、领先、革命性”。

15 个样本告诉了我们什么

这是结构观察，不是成功公式。样本来自已经增长的仓库，存在明显幸存者偏差。

12/15首屏有图
11/15首屏有徽章
4/15首屏有安装命令
3/15首屏可点 Demo
不能推出：加图就会涨星、减少徽章就会增长、照抄结构就能传播。转发来源、作者影响力、题材需求与发布时机都可能更重要。

发布前 8 项自查

□ 首屏一句话写读者收益，不只写技术栈
□ 截图来自真实运行，不是抽象插画
□ 有一个明确安装或体验入口
□ 数量、版本、日期与数据源一致
□ 所有站内链接已批量检查
□ 仓库简介和 Topics 是目标用户会搜的词
□ 效果、性能与准确率有可复现证据
□ 明确项目不做什么、哪些仍待验证

把这套审查装进 Codex。
