为什么 Skill 没出现？

先别反复重装。把“CLI 找到、文件落盘、客户端读取、任务完成、环境可用”拆开检查，通常几分钟就能知道卡在哪一层。

先记住这个判断
发现 ≠ 安装
安装 ≠ 自动触发
触发 ≠ 任务完成
环境阻断 ≠ Skill 失败

01 / TRACE

按顺序走完 5 个检查点

上一步没有证据，就不要跳到下一步猜原因。

1. CLI 能不能发现目标 Skill？

npx skills@1.5.22 add \
  https://github.com/sanhuang520-ship-it/awesome-chinese-ai-tools \
  --list

列表里没有目标名称：先查仓库目录、SKILL.md 与 frontmatter。这仍是发现问题，不是 Codex 自动触发问题。

2. 文件是否真的落盘？

test -f ~/.agents/skills/chinese-typography/SKILL.md \
  && echo "installed"

本站在 skills CLI 1.5.22 的本机实测路径是 ~/.agents/skills/。工具版本可能改变行为，以你的本机结果为准。

3. 新会话是否主动读取？

请检查下面这段网页 CSS 的中文排版问题，
只做审查，不修改文件。明确列出问题、理由和建议值：
body { font-family: Arial, sans-serif; font-size: 14px;
line-height: 1.35; word-break: break-all; }

任务中不要写 chinese-typography。点名只能测试“按指令读取”，不能证明自然任务中的自动选择。

4. 读到了，任务是否真正完成？

检查主要验收点是否交付、是否越界、是否因为任务太大而中断。本仓库有两项大任务未完成，但缩小复测通过；原失败仍然保留。

5. 模型有没有真正开始执行？

账户用量、网络或平台错误如果发生在模型输出前，应记为“环境阻断 / 未执行”。它不能支持“Skill 失败”的结论。

02 / LOCATE

看到什么，就停在哪一层

不要用后面的术语描述前面的故障。

观察当前结论下一步
--list 没有目标名称发现失败检查目录名、SKILL.md 与 frontmatter
能列出，但安装目录没有文件安装失败保留命令、CLI 版本与完整错误
文件存在，但自然任务未读取自动触发未确认新会话复测；记录客户端版本、任务原文和已安装集合
读取正确 Skill，但交付缺失完成失败或部分完成缩小任务复测，但不删除原失败
模型开始前账户或平台报错环境阻断等待环境恢复；不要归因给 Skill
主动读取且覆盖验收点该任务下通过保存版本、逐字任务、输出与不能外推的边界

04 / AVOID

三种越排查越乱的做法

NO. 1

只看安装成功提示

成功提示没有证明文件位置，也没有证明客户端读过。

NO. 2

任务里直接点名

这样测到的是明确调用后的执行，不是自动选择。

NO. 3

把所有非零退出都算失败

环境阻断、任务过大和 Skill 行为是不同问题，必须分开记录。
