01 / 循环

学习不是把内容再看一遍

每轮只处理一个可消化的概念。输入之后必须让学习者提取、应用和修正；否则“看着熟悉”很容易被误认为“已经掌握”。

01

输入

一次只学一个概念，控制体量。

02

回忆

合上材料，用自己的话复述。

03

拆解

只针对暴露出的卡点重讲。

04

输出

写代码、解释或完成小任务。

05

归因

判断是概念、粗心还是不会用。

06

复习

第 2、4、7、15 天再次提取。

07

交付

用完整项目验证能否独立完成。

02 / 示例

两周 SQL：第一轮应该先问什么

以下只展示校准阶段，不假设用户的职业目标、基础或可用时间。收到回答后，计划才能确定练习数据、项目范围和节奏。

用户原始任务

我想用两周入门 SQL，但不想再看完教程就忘。先了解我的目标和基础，再带我制定能动手练习的计划。

校准响应应覆盖
  1. 两周后想用 SQL 完成什么实际任务？
  2. 是否写过 SELECT、WHERE、GROUP BY 或 JOIN？
  3. 每天能投入多久，是否有可运行 SQL 的环境？
  4. 希望用什么产出验收：分析报告、查询题，还是一个小项目？
回答之前不虚构一张通用课表，也不声称“两周能学会”。
