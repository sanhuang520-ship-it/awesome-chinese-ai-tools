四步安装与核对

以下命令使用本站仓库作例子。一次只处理当前需要的 Skill，保留 CLI 版本与本机观察结果。

STEP 01

先列出，不要盲装全部

npx skills add https://github.com/sanhuang520-ship-it/awesome-chinese-ai-tools --list

确认目标名称，也能及早发现仓库结构不被 CLI 识别。

STEP 02

一次只装一个

npx skills add https://github.com/sanhuang520-ship-it/awesome-chinese-ai-tools --skill chinese-typography

Skill 越多，客户端用于发现描述的上下文预算越紧。本次 Codex 实测出现过 description 被缩短的警告。

STEP 03

核对实际文件

ls -la ~/.agents/skills/chinese-typography ls -la ~/.claude/skills/chinese-typography

本机实测文件位于 ~/.agents/skills/；Claude 目录可见符号链接。版本变化后请以本机结果为准。

STEP 04

测试自动触发

请审查这个中文网页的字体、行高、断行、标点和中英混排问题。

不要在任务里说出 Skill 名称。观察 AI 是否主动读取正确说明，再检查输出是否真正完成任务。

安装后不会自动跟随仓库更新

2026-08-13 隔离复测中，固定版本 skills@1.5.22 安装的 13 项与当前仓库逐字一致；但 8 月 8 日留下的全局副本已经是 0/13 一致，因为仓库后来补充了元数据并修订内容。

npx --yes skills@1.5.22 update -p -y

项目级受控复测中，13 个历史夹具文件夹更新后 13/13 与当前仓库完整一致，全局文件哈希未变。这个命令只适用于有 skills-lock.json 的项目级安装；本轮没有验证全局 update -g。

先确认版本与来源：未固定版本的 npx skills --version 可能命中本机缓存。复现问题时记录实际版本，必要时固定已知版本；确认上游可信后，再使用 CLI 的更新或重新安装流程。

没有触发时，按这个顺序查

① CLI 的 --list 是否能看到目标名称
② ~/.agents/skills/<name>/SKILL.md 是否存在
③ 客户端入口是否能看到同一个 Skill
④ 重启客户端后，用不点名名称的自然任务复测
⑤ 减少同时安装的 Skill，避免描述预算拥挤
⑥ 记录客户端版本、任务原文和错误，不只写“不能用”
