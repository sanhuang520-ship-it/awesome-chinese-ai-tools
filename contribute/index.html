TASK 01 · COMPATIBILITY约 15 分钟

在 Claude Code 或 Cursor 复测一个原创 Skill

适合：已经在使用 Claude Code、Cursor 或其他 Agent 客户端的人。

  1. 从13 个首次试用任务选择一个。
  2. 只安装这个 Skill，重启客户端。
  3. 复制自然任务，不主动写 Skill 名称。
  4. 记录是否读取、是否完成和脱敏结果。
完成标准
  • 客户端与可确认版本
  • 逐字任务与是否点名
  • 自动触发、完成状态、证据边界
提交兼容性结果 →先看测试方法
TASK 02 · INSTALL约 10 分钟

验证 Windows 或 Linux 的实际安装路径

适合：可以在 Windows、WSL 或 Linux 运行 Node.js / npx 的人。

  1. 记录操作系统、终端、Node 与 skills CLI 版本。
  2. 用 --list 查看仓库，再只安装一个 Skill。
  3. 检查实际落盘路径，以及是目录、副本还是符号链接。
  4. 不运行目标 Skill 里的脚本。
完成标准
  • 命令与版本可重放
  • 实际路径和文件类型明确
  • 成功、失败或权限阻断均如实记录
提交安装环境结果 →先看当前安装证据
TASK 03 · FACT CHECK约 10 分钟

复核一个第三方目录条目

适合：不想安装或运行任何代码，只愿意做只读核对的人。

  1. 从完整清单选一个非本站原创条目。
  2. 确认来源仓库可访问且确实存在 SKILL.md。
  3. 对照原作者 description，检查中文说明是否准确。
  4. 检查链接是否含推广或追踪参数。
完成标准
  • 给出条目名称与公开来源
  • 分别写“确认”“错误”或“无法确认”
  • 不根据项目名猜测功能
提交事实复核 →查看收录标准

我们如何处理结果

  • 维护者先核对来源、任务、版本、脱敏与证据边界，再决定是否进入兼容性数据或目录。
  • 单次结果只写成该环境、该版本和该任务下的观察，不外推为准确率、质量认证或普遍兼容。
  • 发现环境阻断时单独记录，不把模型开始执行前的账户、网络或平台错误算作 Skill 失败。
  • 贡献与 Star 完全独立；不会要求互 Star、点赞换收录或推广链接。
