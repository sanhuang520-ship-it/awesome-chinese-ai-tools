从一次成功任务开始。

Skill 不是一段更长的 Prompt，而是把已经有效的流程、命令、边界和好输出变成可重复使用的工作方式。

# 工作流
1. 确认输入
2. 执行步骤
3. 验证结果
4. 说明边界
OpenAI 当前文档：Skill 是含 SKILL.md 的目录，name 与 description 是必填项，脚本、参考资料和资源是可选扩展。官方 Build skills 文档 ↗
01 / START

先选择值得固化的工作

选择已经做成功、以后还会重复、而且有明确验收方式的流程。

适合

发布清单、代码审查、中文排版、固定报表、重复测试命令、团队写作范例。

先不要做

一次性临时任务、还没跑通的想法、没有稳定输入输出的泛泛知识。

02 / WRITE

description 负责“何时选我”

可匹配

description: 中文排版规范助手。
当用户要排版、中文网页样式、字体、
中英混排或 CJK 断行时使用。
不处理通用品牌设计。

太空泛

description: 一个强大、专业、
全面、最好用的内容助手。

主要场景和触发词应前置，边界也要明确。Codex 先看名称与描述，选择后才读取完整说明。

03 / SPLIT

主说明保持短，重内容按需加载

my-skill/
├── SKILL.md          # 必需：元数据与主流程
├── scripts/          # 可选：稳定代码
├── references/       # 可选：参考文档
├── assets/           # 可选：模板和资源
└── agents/openai.yaml # 可选：外观与依赖

该结构来自 OpenAI 当前文档。不要把所有资料都塞进主文件，也不要为了结构漂亮拆分五行说明。

04 / TEST

测试三件事，不只看安装

能否发现

列出目录，确认名称与 frontmatter 可识别。

能否自动选择

用自然任务测试，不在任务里直接写 Skill 名称。

能否完成

检查验收点与边界；自动读取不等于任务完成。

npx skills add https://github.com/owner/repo --list
npx skills add https://github.com/owner/repo --skill my-skill

路径与客户端行为可能随版本变化，具体结果以你的本机为准。

05 / IMPROVE

用真实结果反向修改

没有触发，先修改 description 的范围与触发词；触发但交付失败，修改主流程、输入校准和验收步骤。不要用一次成功或失败推断跨版本准确率。仓库的 中文排版案例 保留了逐字任务和单版本边界。
