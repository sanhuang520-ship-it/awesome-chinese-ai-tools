# 发布操作手册

正文在同目录 `article.md`，也在仓库 [blog/skill-pitfalls.md](https://github.com/sanhuang520-ship-it/awesome-chinese-ai-tools/blob/main/blog/skill-pitfalls.md)。
**三个平台的正文完全一样，只有标题/标签/开头一句不同。**

---

## 建议顺序：掘金 → Linux.do →（观察一天再决定要不要发知乎）

不要三个平台同一小时全发。先发掘金，看看评论里有没有人指出事实错误——
这篇文章的卖点就是"我实测过"，如果哪条被打脸，先改再往下发。

---

## ① 掘金（juejin.cn）— 首发，优先级最高

**为什么先发这里**：技术踩坑类内容的主场，读者就是会装 skill 的人。支持直接粘 Markdown。

- 入口：右上角「创作者中心」→「写文章」→ 选 **Markdown 编辑器** → 全文粘贴
- **标题**（直接用，钩子最强的那版）：

```
7 万星仓库教的安装路径是错的——整理 116 个 AI Skill 的踩坑记录
```

- **分类**：后端 / 人工智能（选「人工智能」）
- **标签**（最多 5 个，按这个填）：`人工智能` `AI编程` `GitHub` `开源` `前端`
- **封面**：可以用仓库里的 `og.png`
  下载：https://sanhuang520-ship-it.github.io/awesome-chinese-ai-tools/og.png
- **摘要**（发布弹窗里会让填）：

```
照着 7.1 万星仓库的文档装 Claude Skill，装完没生效——它写的路径在我这台 macOS 上根本不存在。这是整理 116 个 AI Skill 过程中踩到的 7 个坑，包括一个让我两个月的访问数据全废的静默失败。
```

⚠️ 掘金对纯广告很敏感。**项目地址放在文末就行，不要在开头放**（现在的版本已经是这样，别改）。

---

## ② Linux.do — 第二个发

**为什么**：氛围最好，愿意认真读技术细节，而且允许带项目链接。

- 板块：**开发调优**（不要发「资源荟萃」，那边偏分享链接，这篇是经验帖）
- **标题**（这里换一个更口语的，社区风格不同）：

```
整理了 116 个 AI Skill，说说踩到的 7 个坑（含一个 7 万星仓库的文档错误）
```

- 直接粘 Markdown，Linux.do 原生支持
- **开头加这一句**（社区习惯先自报家门）：

```
自己在做一个中文 AI Skills 库，整理过程中踩了些坑，记录一下，有几条可能能帮你省点时间。
```

---

## ③ 知乎 — 看前两个的反馈再决定

**为什么放最后**：知乎编辑器对 Markdown 支持差，代码块要一个个重贴，工作量不小。前两个平台没水花的话，不值得花这个时间。

如果要发：
- 形式选**文章**，不要发想法
- **标题**（知乎标题党一点效果更好）：

```
我照着 7 万星的 GitHub 文档操作，结果发现它是错的
```

- 话题：`人工智能` `Claude` `GitHub` `程序员`
- 代码块用知乎自己的「代码」组件重新贴，别指望粘贴保留格式

## 一句实话

这篇文章能不能带来 star，取决于坑一（7 万星文档写错路径）这个钩子有没有人共鸣。

那我们就该考虑换个更痛的切口，而不是继续写第二篇。
